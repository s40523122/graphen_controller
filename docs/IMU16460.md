# FSS-IMU16460-C 硬體與通訊協議

原極科技 FSS-IMU16460-C（6 軸 MEMS IMU，UART 介面）的硬體現況、通訊協議與測試向量。
驅動程式見 [imu16460_core](../src/imu16460/imu16460_core/)（純 C++）與 [imu16460_hardware](../src/imu16460/imu16460_hardware/)（ros2_control plugin），整合方式見 [ARCHITECTURE.md §2.7](ARCHITECTURE.md#27-imu16460sensorinterfaceimu16460_hardware)。

協議內容取自產品手冊 V1.1，已整理並以手冊範例驗證；與手冊不一致的地方以本文件為準。

> ⚠️ **未經同意，不要對實機送出會改變持久設定的指令**（存 FLASH、改鮑率、改坐標系、重啟）。開發與測試時只做讀取。`imu16460_cli` 的這類指令必須帶 `--yes` 才會送出；hardware plugin 不會送任何命令。

---

## 1. 硬體現況（已實測確認）

目標平台：NVIDIA Jetson Orin（aarch64, Ubuntu 22.04, ROS 2 Humble）。

| 項目 | 值 |
|---|---|
| 接線 | Orin 40-pin：Pin4=5V→IMU VIN、Pin6=GND、Pin8(TX)→IMU RX、Pin10(RX)←IMU TX |
| 裝置 | `/dev/ttyTHS1` |
| 鮑率 | **921600**（非手冊預設的 115200，已由掃描確認） |
| 輸出 | 數據流模式，約 **1000 Hz** 的 A1 幀 |
| 系統 | `nvgetty` 已停用；使用者需在 `dialout` 群組 |

## 2. 通訊協議

### 2.1 串口參數
8 data bits、1 stop bit、無 parity、無流量控制。支援鮑率：115200 / 230400 / 460800 / 921600 / 1500000。

### 2.2 通用幀格式（全部 little-endian）

| offset | 型別 | 內容 |
|---|---|---|
| 0–1 | uint8×2 | 幀頭：IMU→主機 `AA 55`；主機→IMU `55 AA` |
| 2–3 | uint16 | 幀 ID |
| 4–5 | uint16 | payload 長度 n |
| 6 … 6+n-1 | bytes | payload |
| 6+n … 9+n | uint32 | CRC32 |

### 2.3 CRC32（已用手冊範例逐一驗證）
- 標準反射式 CRC32 查表（多項式 0xEDB88320，即手冊附錄那張 `crc32_tab`）
- **初值 = 1**（不是 0xFFFFFFFF），**無最終 XOR**
- 計算範圍：從幀頭第一個 byte 到 payload 最後一個 byte（不含 CRC 本身）
- CRC 以 little-endian uint32 附在幀尾

```cpp
uint32_t crc = 1;
for (size_t i = 0; i < len; ++i) crc = tab[(crc ^ buf[i]) & 0xFF] ^ (crc >> 8);
```

### 2.4 IMU 輸出幀 ID

| ID | payload 長度 | 意義 |
|---|---|---|
| `0x0002` | 44 | A1：AHRS 數據流（主要資料） |
| `0x00FF` | 42（依型號可能不同） | S1：系統狀態 |
| `0x7530` | 24 | P1：讀取參數的回應 |
| `0x753D` | 4 | 設定參數 / 存 FLASH 的回應 |
| `0x0064` | 4 | 一般命令回應（如 CMD 3） |

### 2.5 A1 payload（ID 0x0002, 44 bytes）

| offset | 名稱 | 型別 | 單位 |
|---|---|---|---|
| 0 | timer | uint32 | µs（裝置內部時間） |
| 4 | pitch | float | ° |
| 8 | roll | float | ° |
| 12 | yaw | float | °（無磁力計，相對值，會漂移） |
| 16/20/24 | ax/ay/az | float | g（**含重力**） |
| 28/32/36 | gx/gy/gz | float | °/s |
| 40 | temp | float | ℃ |

輸出資料已完成單位換算、出廠校正、溫補，以及內部低通濾波（預設 47 Hz，延遲約 7 ms）。

### 2.6 主機→IMU 命令幀
幀頭 `55 AA`，ID = CMD，長度固定 `0x0018`（24 bytes）。payload 如下：

| offset | 名稱 | 型別 |
|---|---|---|
| 0 | Param1 | float（設定值） |
| 4 | Param2 | float（保留，0） |
| 8 | Param3 | uint32（參數索引） |
| 12 | Param4 | uint32（0） |
| 16 | Param5 | int32（0） |
| 20 | Param6 | int32（0） |

| CMD | Param1 | Param3 | 功能 | 預期回應 |
|---|---|---|---|---|
| 1 | 0 | 0 | 取得一次系統狀態 | ID 0x00FF |
| 2 | 0 | 0 | 取得一次 AHRS | ID 0x0002 |
| 3 | mode | 0 | mode=1 數據流；mode=100 命令模式 | ID 0x0064，payload = `[cmd u16][result u16=1]` |
| 5 | 0 | 0 | 存參數到 FLASH | ID 0x753D，payload = `[0x0005][0x0001]` |
| 6 | 0 | index | 讀取參數 | ID 0x7530，P1 格式，Param1 = 值 |
| 9 | 0 | 0 | 軟體重啟 | 無 |
| 14 | value | index | 設定參數 | ID 0x753D，payload = `[0x7534][index u16]` |

參數索引（CMD 6 / CMD 14 的 Param3）：

| index | 意義 |
|---|---|
| 3 | 鮑率（需 save + reboot 才生效） |
| 4 | 坐標系朝向 101–124（101 = 預設） |
| 8/9/10 | 陀螺 X/Y/Z 零偏標定值（°/s，唯讀用途） |
| 21 | AHRS 輸出頻率 Hz（常用 1/10/50/100/200/500/1000） |
| 31 | 內部濾波器設定（預設 0xBB = 47 Hz；對照表手冊未附） |

注意：
- 手冊註記「**讀取參數時 IMU 會關閉數據流**」，讀完後須送 CMD 3 mode=1 恢復（`Driver::read_param()` 會自動處理）。
- 命令回應會和 A1 數據流交錯出現，解析器需依 ID 分派。
- 頻率與鮑率建議對應：1000 Hz→921600、200～500 Hz→460800、100 Hz→115200。

### 2.7 測試向量

全部來自手冊，CRC 已驗證正確；單元測試使用的就是這些向量（[test_vectors.hpp](../src/imu16460/imu16460_core/test/test_vectors.hpp)）。

```
# A1 數據流幀
AA 55 02 00 2C 00 6D 89 16 05 8F C2 65 40 14 AE 07 BF 5C 0F B2 43 25 06 81 3D
BC 74 13 3C 60 E5 80 BF EC 51 38 BD 0A D7 A3 BB CD CC CC BC D7 A3 EE 41 0C BF 84 80
# 預期解析：timer=85363053, pitch=3.59, roll=-0.53, yaw=356.12,
#          ax=0.063, ay=0.009, az=-1.007, gx=-0.045, gy=-0.005, gz=-0.025, temp=29.83

# CMD 1 取得系統狀態（payload 全 0）
55 AA 01 00 18 00 [24×00] BD DB 31 34
# CMD 3 mode=1（Param1=1.0f）
55 AA 03 00 18 00 00 00 80 3F [20×00] 52 D8 8E E8
#   回應：AA 55 64 00 04 00 03 00 01 00 E7 87 E3 AD
# CMD 5 存 FLASH
55 AA 05 00 18 00 [24×00] C9 2F E6 32
#   回應：AA 55 3D 75 04 00 05 00 01 00 5A CF B1 7C
# CMD 6 讀 index 21
55 AA 06 00 18 00 [8×00] 15 00 00 00 [12×00] 66 CB 46 AC
#   回應（值 50.0f）：AA 55 30 75 18 00 00 00 48 42 [4×00] 15 00 00 00 [12×00] 31 2F A2 0A
# CMD 6 讀 index 4
55 AA 06 00 18 00 [8×00] 04 00 00 00 [12×00] 69 64 09 E4
#   回應（值 115.0f）：AA 55 30 75 18 00 00 00 E6 42 [4×00] 04 00 00 00 [12×00] B2 2F 2D 4E
# CMD 14 設鮑率 115200（Param1=115200.0f, Param3=3）
55 AA 0E 00 18 00 00 00 E1 47 [4×00] 03 00 00 00 [12×00] 56 2B 4D 93
#   回應：AA 55 3D 75 04 00 34 75 03 00 A7 98 2A 54
# CMD 14 設頻率 100 Hz（Param1=100.0f, Param3=21）
55 AA 0E 00 18 00 00 00 C8 42 [4×00] 15 00 00 00 [12×00] 0A 2B 2C 8D
#   回應：AA 55 3D 75 04 00 34 75 15 00 70 2D B2 48
# CMD 14 設坐標系 115（Param1=115.0f, Param3=4）
55 AA 0E 00 18 00 00 00 E6 42 [4×00] 04 00 00 00 [12×00] 46 6A 4E 86
#   回應：AA 55 3D 75 04 00 34 75 04 00 60 0E 6B 1B
```

手冊中 5.1.4 系統狀態的「回應範例」長度與內容不一致，**不要拿來當測試向量**。

### 2.8 手冊已知錯誤（以本文件為準）
- 引腳表把 TX 寫成「接收異步數據輸出」；實際上 Pin4 是 IMU 的 TX 輸出。
- S1 註解提到的是另一型號 IMU614E，S1 長度與保留欄位須以實機回應為準。
- `RC_CEHCK` 等拼字錯誤無意義。

## 3. 待實機驗證

以下項目不要自行假設為正確；程式碼中以 `// TODO(verify-on-hw):` 標記。

1. **坐標系方向**：手冊範例靜置時 az ≈ -1g，代表裝置 z 軸朝下，不符合 ROS REP-103 的 FLU。`axis_transform: frd_to_flu` 的做法是 y、z 取負（繞 x 轉 180°）。必須用六面重力測試確認，再決定預設值（目前為 `none`）。
2. **Euler 定義**：手冊沒有說明 pitch/roll/yaw 的旋轉順序與正方向。預設先用 ZYX（yaw→pitch→roll），可用 `euler_order` 切換。要實際轉動模組驗證。驗證完成前，`imu_sensor_broadcaster` 的 orientation 共變異數第一項設為 -1（不提供姿態）。
3. **時間戳**：Humble 的 `imu_sensor_broadcaster` 以 controller_manager 的更新時間打時間戳，無法傳遞裝置 timer。需要精確時間戳時，改用獨立 node 直接發布。
4. **S1 系統狀態的實際長度**：`imu16460_cli status` 目前只印出原始 payload。
5. **共變異數**：`graphen_bringup/config/imu/imu16460.yaml` 中角速度 / 加速度的共變異數是暫定值，要以實測靜態資料取代。

### 3.1 方向性驗證工具（`imu_orientation_check`）

IMU 裝在機器人上後無法做六面重力測試，改用機器人做得到的小幅動作，驗證 `/imu_sensor_broadcaster/imu` 轉到 `base_link`（以 TF 套用 `imu_rpy`）後是否符合 REP-103 FLU。只訂閱 topic、查詢 TF，不送任何命令。

```bash
ros2 launch graphen_bringup bringup.launch.py use_mock_imu:=false   # 本體預設 mock；本體也用實機時加 hardware:=real
ros2 run graphen_bringup imu_orientation_check
```

依提示操作（機器人需固定在吊架上，傾斜約 10–15°；每一步可輸入 `s` 跳過）：

| 步驟 | 加速度（比力） | 陀螺積分 | 姿態變化 |
|---|---|---|---|
| 直立靜置 | `≈ (0, 0, +g)` | `≈ 0`（記為零偏） | quaternion 推算的「上」方向與加速度一致 |
| 前傾 | `ax < 0` | `+y` | `+y` |
| 右傾 | `ay > 0` | `+x` | `+x` |
| 原地左轉 | 不變 | `+z` | `+z` |

結束時會列出每個項目的「預期 / 觀測軸」並提示：加速度錯誤 → `axis_transform` 或 `imu_rpy`；只有陀螺錯誤 → 陀螺的正方向定義和加速度計不同；只有姿態錯誤 → `euler_order` 或 `write_sample()` 中 pitch / yaw 取負的假設。觀測軸為 `none` 代表動作太小。門檻都是 ROS 參數（`min_tilt_deg`、`min_yaw_deg`、`gravity_tolerance`、`max_static_gyro`、`max_axis_error_deg`、`motion_duration` 等）。

## 4. 實機驗收條件

1. `imu16460_cli monitor` 顯示約 1000 Hz、CRC 錯誤率 < 0.1%。
2. `ros2 launch graphen_bringup bringup.launch.py use_mock_imu:=false` 後，`/imu_sensor_broadcaster/imu` 以 controller 頻率穩定發布，單位為 rad/s 與 m/s²。
